## 무엇을 하는 명령인가

`status`는 현재 브랜치, HEAD, 정확한 current-HEAD snapshot readiness, runtime 지원 상태, backend, historical manifest 개수, knowledge readiness, event-ledger activity, embedding/store/cache 상태, security posture를 빠르게 보여줍니다.

## 언제 쓰는가 / 언제 쓰지 않는가

### 언제 쓰는가

- 저장소의 운영 상태를 빠르게 보고 싶을 때
- store가 로드되었는지, 검색 준비가 되었는지 확인하고 싶을 때
- 설정 표면을 파일을 열지 않고 확인하고 싶을 때

### 언제 쓰지 않는가

- 더 깊은 진단이 필요할 때. <a href="/ko/docs/commands/doctor">`doctor`</a>를 사용하십시오.
- 설정값을 바꾸고 싶을 때. <a href="/ko/docs/commands/config/set">`config set`</a>을 사용하십시오.

## 기본 구문

```bash
pnpm ragit status [--format text|json|both] [--cwd <path>]
```

## 인자와 옵션

- `--format text|json|both`: 사람이 읽는 출력, JSON, 둘 다 중 하나를 선택합니다.
- `--cwd <path>`: 다른 저장소를 대상으로 실행합니다.

## 입력/출력 계약

- positional 입력도 JSON payload 입력도 없습니다.
- JSON 출력에는 `branch`, `head`, `snapshot`, `runtime`, `backend`, `zvec`, `supported_types`, `docsAuthority`, `knowledge`, `events`, `manifests`, `embedding.configured`, `embedding.store`, `embedding.cache`, `embedding.ready`, `embedding.needsMigration`, `security`, `format`이 포함됩니다.
- `runtime`은 현재 및 최소 Node 버전, 현재 `platform/arch`, 두 개의 지원 native target, 종합 `supported` 상태를 보고합니다.
- `snapshot.status`는 HEAD 또는 exact manifest가 없으면 `missing`, manifest가 malformed/mismatched/future 상태이면 `invalid`, exact valid manifest가 있지만 usable canonical store가 없으면 `store-unavailable`, 둘 다 사용할 수 있을 때만 `indexed`입니다.
- `zvec.searchReady`와 `knowledge.durableReady`는 `snapshot.status: indexed`일 때만 true입니다. `manifests` 개수는 historical context이며 unrelated manifest가 current HEAD를 ready 상태로 만들지 않습니다.
- `embedding.cache`에는 `enabled`, `dir`, `namespaceId`, `entryCount`, `batchPolicy`, `retryPolicy`, `writable`, `namespaceReadable`가 들어 있습니다.
- `security`는 `maskingConfigured`, `remoteEmbeddingPolicy`, `providerEgressClass`, `outputRemasking`, `quarantineEntries`, `lastAuditAt`, `legacyUnsafeState`를 보고합니다.
- 에이전트는 보통 `--format json`을 사용하는 편이 좋습니다.

## 대표 사용 예시

사람용 터미널 예시:

```bash
pnpm ragit status
```

에이전트 호출 예시:

```bash
pnpm ragit status --format json
```

## 실패/주의 사항

- `status`는 요약 명령이지 복구 명령이 아닙니다.
- `status`는 네 가지 snapshot diagnostic state 모두에서 성공 종료하며 readiness를 판단하기 위해 embedding provider를 호출하지 않습니다.
- Detached HEAD는 `branch: null`, unborn repository는 `head: null`로 보고합니다. Dirty worktree metadata는 사용 가능한 committed snapshot을 무효화하지 않습니다.
- store가 로드되었다고 해서 정확한 현재 HEAD가 인덱싱되었다는 뜻은 아닙니다. 의도한 문서 변경을 커밋한 뒤 <a href="/ko/docs/commands/ingest">`ingest`</a>를 실행하십시오.
- event counter는 append-only operational ledger를 반영할 뿐 semantic snapshot delta를 대신하지 않습니다. 자세한 시간축이 필요하면 <a href="/ko/docs/commands/timeline">`timeline`</a>을 사용하십시오.
- `embedding.needsMigration=true`이면 새로운 provider contract에 맞게 쓰기 경로를 쓰기 전에 <a href="/ko/docs/commands/migrate/embeddings">`migrate embeddings`</a>를 실행하십시오.
- cache를 기대했는데 `embedding.cache.enabled=false`라면 <a href="/ko/docs/commands/doctor">`doctor`</a>의 `embedding.cache-dir`, `embedding.cache-namespace` check를 함께 확인하십시오.
